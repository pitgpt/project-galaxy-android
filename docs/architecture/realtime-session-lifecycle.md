# Realtime session lifecycle and concurrency

## Decision

Galaxy tracks client-reported active Realtime sessions with short Redis leases. This is an application-level concurrency guard, not proof that a provider-side WebRTC transport is currently connected.

## Lease policy

- Maximum active sessions per account: 2 by default.
- Lease duration: 90 seconds.
- Android heartbeat interval: 30 seconds while the Realtime connection is established.
- A missed heartbeat expires the lease automatically.
- Explicit close releases the lease immediately.
- Redis is authoritative in production. Redis failures fail closed for creation and heartbeat operations.
- Session identifiers are generated by Galaxy, are opaque, and are scoped to the authenticated account.
- A caller cannot renew or close another account's session.

## Lifecycle

1. Authenticate the caller and validate the requested character and voice.
2. Atomically reserve a concurrency slot in Redis before requesting a provider credential.
3. If no slot is available, return HTTP 429 without calling the provider.
4. Request the ephemeral provider credential.
5. If the provider request fails, release the reserved slot before returning a sanitized error.
6. Return the Galaxy session identifier with the ephemeral credential.
7. Android starts WebRTC and renews the lease with an authenticated heartbeat every 30 seconds while connected.
8. On disconnect, Android calls the authenticated close endpoint. If the app is killed or the network disappears, the 90-second lease expires.
9. Heartbeat and close are idempotent with respect to a session owned by the caller. Unknown or expired sessions return a non-sensitive not-found response.

## Redis representation

Use one sorted set per account. The key contains only a SHA-256 digest of the authenticated user ID. Members are Galaxy-generated session IDs; scores are lease-expiration Unix timestamps in milliseconds.

Every mutation is atomic Lua:
- Reserve removes expired members, checks the active count, then inserts the new lease if capacity remains.
- Heartbeat verifies membership, then updates the expiry score.
- Close removes the member.
- The sorted-set key receives an expiry longer than the lease so abandoned account keys are eventually reclaimed.

No raw user ID, provider credential, SDP, or authorization header is stored in Redis.

## API contract

- `POST /v1/realtime/sessions`: reserve a slot and create the ephemeral credential.
- `POST /v1/realtime/sessions/{session_id}/heartbeat`: renew the caller-owned lease.
- `DELETE /v1/realtime/sessions/{session_id}`: release the caller-owned lease.

All lifecycle endpoints require the same authenticated Galaxy bearer token. The client never supplies a user ID.

## Limits and failure semantics

- `REALTIME_MAX_ACTIVE_SESSIONS`: defaults to 2; must be at least 1.
- `REALTIME_SESSION_LEASE_SECONDS`: defaults to 90; must be at least 30.
- Production requires Redis. Redis errors fail closed with HTTP 503.
- Capacity exhaustion returns HTTP 429 with a retry hint.
- Provider failure must release a reservation, including unexpected response shapes.
- The daily credential issuance quota remains independent of concurrency. A failed provider attempt may still consume a credential-request quota, preventing retries from bypassing abuse controls.

## Trust limitation

A heartbeat proves only that an authenticated client is renewing its lease. It does not prove that audio is flowing or that OpenAI still considers the WebRTC session connected. The lease is deliberately conservative: it bounds stale reservations after crashes and network loss without claiming provider-side observability.
